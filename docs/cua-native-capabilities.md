# CUA native capability map for the thin DTW entry

Source reviewed: local read-only CUA checkout `ac967b9006aafa10870aadb5a645b038cba9721a`, especially `crates/cua-driver-core/src/script_tool/{prelude.js,../script_tool.rs}`, `crates/platform-macos/src/tools`, and `Skills/cua-driver/{SKILL,WORKFLOW,MACOS,BROWSER}.md`. This is an API/source map, not a live pass for every route.

| Need | Upstream primitive | One DTW `exec` path | Evidence and caveat |
| --- | --- | --- | --- |
| Discover apps and windows | `list_apps`, `list_windows`, `get_app` | `cua.listApps()`, `cua.listWindows()`, `cua.getApp(...)` in `run_script` | Live Chrome, Obsidian and WPS discovery. PID-only App binding follows the app's current front window; pin a window ID only for a stable target. |
| Read controls and state | `get_window_state`, `find`, `wait_for`, `verify_state` | `app.getState`, `query`, `waitFor`, `verify` | Live narrow AX reads; `query` uses selector `name` while results use `label`. A truncated tree cannot prove absence. |
| Read a large page visually | Window capture within `get_window_state`, plus `zoom` | `app.getState({include_accessibility_tree:false,include_screenshot:true})`, then `result` image; `app.zoom` | Native screenshot and image retention worked on real Bilibili and the large-tree Chrome Agent task. Coordinates are window local and should be grounded in the same capture ID. |
| Narrow a marked image region to controls | `get_window_state` structured `elements[].screenshot_frame`, `actions`, `element_token` | One `run_script` intersects a model-selected PNG rectangle with AXPress-capable rows and returns image-pixel centers plus tokens | Fresh v28 Gemini chose a region in a temporary Chrome screenshot, got one matching control, clicked its token once and independently read the changed heading. This is AX-assisted candidate discovery, not visual-only hit testing; a system picker without a bindable AX tree remains outside it. |
| Semantic and pixel input | `click`, `double_click`, `right_click`, `set_value`, `type_text`, `press_key`, `hotkey`, `scroll`, `drag`, `move_cursor` | `app` methods or allowlisted `cua.call` in `run_script` | Isolated GUI fixture verified semantic input/menu/drag; Bilibili Agent used real like and undo. CUA chooses background when available; foreground actions change shared focus. Read the effect back. |
| Global shortcut/desktop input | Desktop `target:{kind:"desktop",display_id:"primary"}` on allowlisted actions | `cua.call("hotkey"/"click"/"press_key",{target:..., ...})` in `run_script` | Fresh Gemini completed an isolated Obsidian picker by full-display screenshot, Go to Folder and focused Return. Three screenshot-bound clicks on an isolated Chrome canvas had `(0,0)`, `(0,-1)`, `(-2,-1)` pixel errors. Global focus remains shared; a delivered click can have an unverified effect. |
| Native menu | `invoke_menu` | Narrow `operation:"menu"` pass-through | Not callable from `run_script` at this SHA. Native tool resolves the exact path and can activate the app. A fresh Gemini Agent observed the localized Chrome menu path and used it to reload the large-tree fixture, with independent `RELOAD-1` readback. |
| Whole display | `get_desktop_state` | Narrow `operation:"desktop",include_image:true` for first-response PNG, or the original receipt's `result,part:image` | Not callable from `run_script`. Native output has primary-display geometry and a one-use `capture_id`; model summary exposes these without dumping the PNG by default. The real Obsidian picker was captured and operated despite failed window binding. |
| Optional visual region parser | `parse_visual_regions` | No POC route or bundled extension | Upstream can return screenshot-bound text/icon boxes and an `interactive` hint, but the parser needs a separately installed perception extension. Its OmniParser detector artifact is AGPL-3.0-only; this package intentionally omits it. Even the hint does not prove a control will accept a click. |
| Focus, cursor and permissions | `bring_to_front`, cursor API, `check_permissions` | Existing narrow `focus`, `cursor`, `permissions` operations | Ordinary-window focus and permission readback verified. Two overlapping isolated Chrome windows both accepted foreground drags only after each exact window was focused and `verified:true` before its drag. Service-owned modal focus can refuse; the Obsidian picker instead passed via desktop screenshot and keyboard. |
| Fixed batches, browser/CDP, recordings | `run_steps`, browser tools, recording tools | Remain upstream capabilities; not copied into this POC | `run_script` cannot call these. `run_steps` can re-find/retry a stale target. Browser/CDP may be better when explicitly available; a personal Chrome profile needs separate setup. The one-tool native route remains screenshot/AX. |

`run_script` is the single execution language, not another JS bridge. The short Skill and `api.d.ts`/`RECIPES.md` teach its actual signatures and route choices. The facade adds only distribution shape and result ergonomics: one advertised MCP `exec`, a host-owned private SDK worker, optional JSON state, original execution receipts, bounded summaries and on-demand full text/structured/images, plus the small pass-throughs above. It does not change CUA's native input, authorization or retries.

Direct upstream `run_script` is viable for an Agent host willing to expose CUA's broader MCP server and accept its native result/state shape. At this source pin, CUA's tool policy controls both listing and nested invocation: listing only `run_script` under that policy also denies the nested read/action calls. A small host facade can expose only `exec` while retaining the allowed nested calls; alternatively, upstream could separate listing policy from invocation policy. That would make the facade smaller, but is not present at the pinned SHA.
