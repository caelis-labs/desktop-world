# DTW thin CUA kernel POC: evidence and stop gates

Date: 2026-10-11. Baseline `b2bee974af969a746c4367f7ec413a2c7a9b3a05`, branch `poc/cua-kernel-thin-integration`; upstream CUA source `ac967b9006aafa10870aadb5a645b038cba9721a` stayed clean and read-only. This is a local POC. No product migration, push, PR, or release occurred.

## Artifact and architecture

`poc/cua-thin` is a Rust MCP adapter linked to upstream `cua-driver-sdk` rlib. Its one `exec` tool delegates the script body to upstream native QuickJS `run_script` and drives an SDK-spawned private worker over inherited pipes. It adds job receipts, per-session JSON state, bounded model output and on-demand text/structured/image retrieval. It has no Node runtime, Go frontend, second JS engine, CuaDriver App launch, or copied set of 59 CUA MCP tools.

Earlier accepted local package: `/private/tmp/dtw-cua-thin-package-20261011-v8` (`bin/dtw` SHA-256 `118ff613e9b11832dcb80da81f752714d34437058e5ceae6f87f07b36e32f824`; private worker SHA-256 `54c93f2a0319e78ed2fb2bf3f20cf77b6017edc2fcd661da1777e99711a3c4b2`). Both binaries passed `codesign --verify`. `build-package.sh` pins source SHA and includes CUA's MIT notice and DTW's MPL-2.0 notice, excluding optional AGPL perception and Spaces. This final local build verified the SHA of a previously built exact-source worker. A fresh offline worker build was attempted but stopped on missing cached `anstream 1.0.0`; it is **not** claimed as a fresh full build. The Rust path dependency is a local POC build input, not a portable release recipe. `adapt_antigravity.py` creates a project-local test adapter without replacing an installed plugin; `agy plugin validate` counted one Skill and one MCP server. MCP `tools/list` returned only `exec`. The Skill is 3,040 bytes. `PATH=/usr/bin:/bin` excluded Node while packaged MCP scripts and native app discovery completed.

The private worker path is necessary for the native cursor API: CUA's direct runtime can return `facility_unavailable` outside its worker environment. The adapter does not pretend to own TCC. Real permission reads reported `Accessibility=true`, `Screen Recording=true`, `source.attribution="host"`, `direct_runtime=true`, `embedded=false`, and a worker executable inside this package. Window screenshots actually succeeded. This proves the tested CLI responsibility chain, not a signed Bot host's grants. CuaDriverLocal.app happened to be installed on this machine but this POC launched and addressed only its private worker, with no App/socket endpoint. An uninstall/no-App machine was not tested.

Final v8 read-only probe inside the restricted shell sandbox repeatedly lost its worker on the second script, with a native `NSWorkspace` LaunchServices notification error and `action_interrupted_notstarted`. The same v8 binaries outside that shell sandbox passed all three Session state scripts, native app discovery (153 apps), and host permission read with Node absent. This isolates a test-environment boundary; it does not establish operation inside every future sandbox. `probe.py` now exits nonzero on incomplete state probes.

## Open gates before migration

1. **Shared desktop/session semantics:** The public `session` label maps to a CUA trusted Session and partitions adapter JSON state and receipts. CUA's same-worker native element tokens can cross labels, and Agents on one desktop can affect one another. This is a documented concurrency behavior rather than a strict isolation requirement for this POC. The product should reobserve before an action after another Agent may have changed a window and start a separate MCP process per independent Agent host.
2. **Native modal and controlled foreground:** Obsidian's location chooser sheet blocked a fresh-palette task. `focus` can prove an ordinary main window is focused, but the chooser did not expose a stable ordinary window handle. The exact `screenshot_context_missing` case needs an upstream fix or a verified alternate target path. WPS and the one-window drag fixture prove controlled foreground can work, but fresh Agent WPS input did not land and the two-overlapping-window foreground test changed only one target. The shared foreground gate remains open.
3. **Cancellation and cursor:** Upstream private-worker calls serialize under one SDK mutex. The adapter can mark cancel and preserve the original receipt, but it cannot promptly interrupt an in-flight action. Cursor API state toggles; visible overlay and two-Session ownership are unverified.
4. **Host/platform:** Signed Bot TCC attribution, real permission refusal, and Windows GUI behavior have not been tested. The worker-disconnect fixture above proves receipt classification but does not prove recovery of an actual uncertain desktop input. Windows has no real machine in this POC, so no Windows pass is claimed.
5. **Installation and broad usability:** The test harness copied and validated the plugin in a new project before the Agent started. No clean-machine, one-command end-user install was exercised. Four fresh Agents completed an isolated Chrome fixture, while the fresh WPS Agent task failed and Obsidian's native chooser stayed unresolved. Selector conventions, asymmetric text-input signatures, and compact-result metadata still need product-level usability review.

The intended minimum release layout remains `bin/dtw`, `libexec/cua-driver`, `skills/desktop-world/SKILL.md`, `mcp.json`, `plugin.json`, `CUA-MIT-LICENSE.txt`, `DTW-MPL-LICENSE.txt`, and `THIRD_PARTY_NOTICES.md`. Source/fixture checks, live app outcomes, and fresh Agent outcomes above are separate. No formal migration should start while the critical gates remain open.
