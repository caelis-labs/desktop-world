# DTW + CUA thin POC: convergence and acceptance

2026-10-11. Worktree branch `poc/cua-kernel-thin-integration`; exact base `b2bee974af969a746c4367f7ec413a2c7a9b3a05`. Read-only upstream CUA source remained clean at `ac967b9006aafa10870aadb5a645b038cba9721a`. No main-workspace migration, push, PR, publication, or existing plugin replacement.

## Decision

Keep DTW's product shape while letting CUA execute the desktop operations. `poc/cua-thin` links the upstream `cua-driver-sdk` Rust rlib and spawns its upstream **private** `cua-driver` worker directly over inherited pipes. Its single advertised MCP tool is `exec`. The default `script` is sent to upstream native QuickJS `run_script`; DTW does not host a second JavaScript engine or reimplement Accessibility, capture, input, permission policy, or action retries. Small `exec` operations pass through upstream `invoke_menu` and `get_desktop_state`, which are not callable from `run_script` at this source SHA. `status`, `result`, and `cancel` stay in the same MCP entry. The adapter adds only bounded presentation, image/full-result retrieval, execution receipts, a small persistent JSON `state`, and packaging.

The public script surface is CUA's `cua.getApp` / App → Window → Element API, with no compatibility promise for old `dtw.app` signatures. Background delivery is CUA's default where safe; `background_unavailable` leads to explicitly targeted foreground input and fresh UI readback. A `session` label maps to a trusted CUA Session and separates adapter state and execution receipts. It does **not** isolate the physical desktop or all native element tokens. Independent Agent hosts should each launch their own MCP process/private worker and reobserve shared focus before input. The upstream worker serializes requests; `cancel_requested` retains the original receipt but does not promptly interrupt an in-flight native call.

This is a reusable, installable **POC candidate for release engineering**, not a signed/notarized product release. Bot-specific TCC ownership, Windows GUI, and the foreground/cursor limits below remain open. The actual responsible host needs Accessibility and Screen Recording grants; an independent Agent cannot inherit a universal one-time grant from Bot. No standalone CuaDriver App is launched or required by this topology. The private worker is chosen because CUA direct runtime can return `facility_unavailable` for its virtual cursor overlay.

## One-tool authoring and installation

The package has `bin/dtw`, `libexec/cua-driver`, `skills/desktop-world/{SKILL.md,api.d.ts,RECIPES.md}`, `mcp.json`, `plugin.json`, CUA MIT and DTW MPL-2.0 notices, and `THIRD_PARTY_NOTICES.md`. No AGPL perception or Spaces dependency is included. The runtime and packaged MCP/Skill probe passed with `PATH=/usr/bin:/bin` (Node absent). The final local package is `/private/tmp/dtw-cua-thin-package-20261011-v28`: adapter SHA-256 `421d749f3730172974848e9bed7d08050657fee3533ff0cdbc635c6c1767be44`, exact-source private worker `54c93f2a0319e78ed2fb2bf3f20cf77b6017edc2fcd661da1777e99711a3c4b2`, Skill `d19d6c48e2362083093e3e8fc7d02a95fe7716bcb990df7e9e6f1b42cdf0f059`. v28 copies the signed v27 binaries and replaces only the three Skill reference files. Both packaged binaries passed `codesign --verify`; the worker SHA was checked against an earlier source build, not rebuilt from scratch in this final package.

`bin/dtw install antigravity --project EXISTING_DIR` copies the package to a project-local `.agents/plugins/desktop-world`, writes its MCP command to that copy, and refuses existing paths (including dangling symlinks). It stages the copy before renaming into place. An isolated final v28 installation at `/private/tmp/dtw-cua-v28-install-6x7s485d` passed `agy plugin validate`: exactly one Skill and one MCP server. v25 also passed a second-install refusal and dangling-symlink preservation test. This CLI is a POC for Antigravity; standard MCP/Skill files can be integrated by another host, but a clean-machine, signed Bot installer and other Agent installers are not claimed.

The short Skill teaches native scripts plus a few copyable recipes. Typical calls are:

```json
{"session":"task","script":"const a=await cua.getApp({pid:123}); const s=await a.getState({query:'Save',max_elements:80,include_screenshot:false}); return s.tree_markdown;"}
{"session":"task","operation":"desktop","include_image":true,"max_image_dimension":1600}
{"session":"task","operation":"result","execution_id":"ORIGINAL_ID","part":"image"}
```

`include_image:true` returns the first PNG in the first terminal response when available; default output stays compact. The `capture_id` returned with a desktop/window image is one-use. The desktop route calls `cua.call("click",{target:{kind:"desktop",display_id:"primary"},x,y,capture_id})` inside the same `exec` script language. The PNG's own `screenshot_width/height` define its coordinate grid; CUA maps that image to native screen points. Do not scale the point again or reuse it after a new observation. A result saying `effect:"unverifiable"` means only delivery. If a modal closes after a click and the old pinned window read fails, inspect `calls before the error took effect`, rebind by PID or recapture desktop, and do not replay the click.

For a bindable window, upstream `get_window_state` also returns each AX element's `screenshot_frame` in the **same returned image's pixels**. The Skill now includes an `exec` script recipe that intersects a model-selected image rectangle with enabled, AXPress-capable elements and returns their labels, tokens, and exact frame centers. A current token is the preferred action target; a capture-bound center point remains available when semantic action fails. This is a candidate list, not proof of visibility or hit acceptance. A truncated/empty AX tree, including the observed unbound Obsidian file picker, cannot be solved by that intersection. Upstream `parse_visual_regions` could return text/icon regions and an `interactive` hint, but it requires the separately installed perception extension, whose OmniParser detector artifact is AGPL-3.0-only; it is not included in this MIT-focused package. A desktop-only picker continues through fresh full-desktop screenshot, capture-bound click or focused keyboard, and readback.

## Remaining limits before a formal release

1. **Foreground and shared screen:** CUA's desktop-scope click is `global_input` and can be affected by focus or another controller. Two overlapping isolated Chrome windows previously returned completed foreground drag receipts, but readback changed only the second window even in a sequential control with no explicit focus (`/private/tmp/dtw-cua-dual-f11cd897/record.json`, `/private/tmp/dtw-cua-dual-8a0b727b/record.json`). A new controlled sequential run explicitly focused and verified each exact window before its drag: both windows independently read `DRAGGED-20261011` (`/private/tmp/dtw-cua-dual-4caf0ea5/record.json`). The Skill now teaches this route. True simultaneous focus ownership across independently running Agents is still shared, so reobserve and coordinate; strict UI isolation is not claimed.
2. **Cancel and cursor:** The private worker serializes native calls. Cancel is an honest request/receipt, not prompt native interruption. Cursor API state toggled and the private worker avoids direct-runtime `facility_unavailable`, but an independent visual overlay readback and ownership under simultaneous Agents remain unverified.
3. **Host/platform/distribution:** The local CLI's permission read was host-attributed and Accessibility/Screen Recording were granted; that does not prove a signed Bot host's TCC behavior. No Windows machine was available, so no Windows GUI pass is claimed. A clean machine without the standalone CUA App and a fully reproducible distributable CUA build/sign/notarization flow are also untested. The POC package uses an exact-source, SHA-checked worker and a local-path SDK build dependency.
4. **Final Skill coverage and Agent discipline:** v25's CLI-installed native task completed with no failed MCP receipts, but its turn did not deliver a critique after an auto-reviewed host `view_file` denial; a same-conversation, text-only continuation supplied the review without further tools. v28's screenshot-region route was completed by a fresh Agent with no failures, and it read the latest Skill. The native chooser and overlapping-window focus wording added after v25 have not each had a separate fresh Agent rerun. The POC cannot technically prevent an Agent from calling its host's unrelated file/window tools; host policy and Agent instructions remain part of the integration.
5. **Other application-specific UI:** The real WPS copied-DOCX editing/saving task passed, and a temporary WPS `cmd+n` opened a blank document in a separate probe. The user-shown WPS home-tab plus overlay was not reproduced in that editor-window probe and has no fresh-Agent acceptance claim.

The core thin topology, one-tool script workflow, real WPS/Obsidian/Bilibili outcomes, image-region candidate workflow, and bounded results are demonstrated. Formal migration/release acceptance remains separate from this local POC; do not mark Windows, Bot permissions, prompt cancellation, cursor overlay, or simultaneous dual-window foreground control as passed.
