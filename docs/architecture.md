# Thin CUA architecture

DTW is a Rust MCP stdio process linked to `cua-driver-sdk` at the exact CUA Git commit in `cmd/dtw/Cargo.toml`. It starts one upstream private `cua-driver` worker over inherited pipes. The upstream worker owns native desktop execution and the QuickJS `run_script` engine. DTW does not port CUA's platform drivers or expose its many low-level MCP tools.

The public MCP surface is one `exec` tool. A default script is passed to upstream `run_script`; the small `menu`, `desktop`, `focus`, and `cursor` operations pass through upstream atomics unavailable from that script. `status`, `result`, and `cancel` address the original execution ID. DTW bounds the default model result and retains full text, structured data, and images for paging. A JSON `state` survives successful scripts in one named DTW Session. Each named Session maps to an upstream trusted Session, but the native desktop and focus remain shared. Running one MCP process per Agent host separates workers and avoids pretending that Sessions isolate the physical UI.

The adapter prefers CUA's background delivery when available. A foreground route must target the observed window or desktop and verify the resulting UI. `capture_id` binds a pixel action to one fresh screenshot and is consumed once. Window screenshots include CUA image-pixel geometry for AX-backed region candidates. A desktop screenshot can reveal an unbindable macOS chooser, but it cannot make its AX tree appear. The Skill teaches capture-bound coordinates and focused keyboard for that case.

The installed package has `bin/dtw` and `libexec/cua-driver` (with `.exe` suffix on Windows), one Skill with two short references, `plugin.json`, `mcp.json`, notices, and checksums. Both build scripts pin and verify CUA source, then copy the upstream MIT and derived-code notices. The macOS script ad hoc signs local binaries; the Windows script leaves test binaries unsigned. The Windows private worker does not confer UIAccess or bypass elevated/AppContainer input restrictions. This is a source implementation and local package recipe; distributor signing, notarization, dependency notice audit, Bot-owned permission validation, and Windows GUI acceptance remain release work.
