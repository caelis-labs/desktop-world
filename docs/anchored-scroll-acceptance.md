# macOS 精确滚动验收

公开入口仍为 `exec(app, source)`，`app.scroll` 保留默认窗口中心，并增加两种互斥的锚点：

- `observation_ref + x + y`：绑定截图中的图像像素坐标，经原截图尺寸和窗口边界映射。
- `observation_ref + element_ref`：绑定原生观察中保留的 AX 对象，以对象与窗口矩形交集的中心为落点；元素不需要声明支持 `press`。

滚动量仍使用原有 wheel steps；正 x 向右、正 y 向下，至少一轴非零。动作消费目标窗口的观察，其他窗口的观察继续可用。Windows/Linux 目前只支持默认中心；不支持的锚点在消费观察之前拒绝。

## 实现边界

复用现有 CUA 输入移植和 scene worker，仅增加锚点适配。像素路线复用截图几何，前台借用后保留原落点。语义路线由原 resident worker 保留 AX 对象；scene worker 在首个实际滚轮事件之前，经私有有界 IPC 请求同一 resident 复核原对象、精确窗口归属、矩形和固定落点。没有复制 AX identity，没有新建全局观察表或输入 owner。

首轮事件投递后不再对后续滚轮重新检查元素位置，避免本次滚动自身移动或虚拟化内容时截断剩余滚动量。原目标窗口、取消和截止时间检查继续生效。检查不证明全部窗口内部裁剪或覆盖关系，也不能消除检查与系统收件之间的竞争；应选择已知可见对象，并独立读回目标区域和邻区。

取消/服务 EOF 时先关闭 guard，再停止 scene，随后停止 resident，防止 resident 归还旧前台时被仍占输入锁的 scene 阻塞。若 OS 无法确认终止，保留原清理错误并使用既有有界退出，不声称已归还；已有 transport 故障的内部退役路径也不升级为全面退出顺序保证。

初次解析前对象已替换会返回 `stale_observation`、`not_dispatched`。若 CUA 已进行输入准备，随后 guard 拒绝，仍保留既有 `unknown` 及原错误，不能据此重放。

## GUI 中收敛的问题

冷态 Chrome 的首个筛选查询可能在网页 AX 树出现前返回完整空页。旧候选 V 与诊断候选 X 均复现：当时仅 53 个浏览器外壳节点，Manual 返回 -25205、Enhanced 返回 -25208；同一实例不重复设置属性，2.3 秒后的查询已出现网页内容，完整分页 668 个节点找到目标。Chrome 的可见静态文本位于 `value`，探针已改为在返回文本字段中做精确唯一匹配。

DTW 仅在近期 Enhanced 尝试后、带筛选条件的首次完整空结果上，在原三秒窗口和调用者截止时间内内部只读重采一次。已有匹配、分页、部分结果和普通查询不额外等待；不再次设置启用属性，也不要求普通原生窗口必须有 WebArea。[Chromium 的异步启用实现](https://raw.githubusercontent.com/chromium/chromium/main/chrome/browser/chrome_browser_application_mac.mm)为该现象提供了实现层解释；本机因果边界以保留的对照为准，未将该主线源码等同于已安装版本源码。

Y 的全部 12 项滚动功能检查通过，但光标 helper 曾在 `NSString.draw → CoreText TAttributes::ApplyFont` 抛出异常后退出，服务将原错误保留为清理失败。异常的更底层原因未确认；后续改用固定十六进制几何字形，移除这条文字布局路径，不降级清理错误或改变输入结果。
