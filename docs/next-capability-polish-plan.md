## 2. 从本次操作得到的优先级修正

本节保留原始 v0.3.4 操作中的问题依据；后续实现状态以上述进展和当前 API 为准。

### 2.1 接入恢复完成，生效来源仍值得更容易诊断

前一轮实际加载的是宿主启用的旧 `desktop-world` 0.1.1 覆盖插件。匹配运行版本的 Caelis 源码明确按“会话指定包 → 已启用宿主覆盖 → 内置包”选择成对 MCP/Skill；不是内置 DTW 缺少当前接口。本次刷新后，已使用恢复的内置工具读取完整讨论。

后续应让宿主诊断直接显示生效来源、包版本、路径及覆盖原因；DTW 继续提供明确合同和 provider 条件。这个选源问题由 Caelis/安装集成负责，不通过 DTW 原生后端加兼容分支解决。验收是在有旧覆盖、无覆盖、显式会话包三种条件下，工具和 Skill 始终对应同一获选包，并能解释选择结果。

### 2.2 当前最直接的操作阻塞是“能看到页面，难以读到相关正文”

本次在 Chrome 中可以发现应用、取得正确会话窗口、收起侧栏、截图并连续滚动，没有重放失败输入。但默认 `look` 的 80 项预算先消耗在浏览器和侧栏控件上；收起侧栏后，正文前部才进入输出。滚动到后续章节时，PNG 已变化，语义输出仍常为 `changed:false`。

这与 `scene.rs` 的实现一致：从当前语义窗口开始，先收集有限原生页，再优先保留可操作节点，输出至多 80 项/24 KiB。当时公共 `look` 只有 `full` 参数；`full:true` 重发完整基线，不是读取后续内容。该基线的完整正文阅读因此需要较多截图和滚动轮次。

`changed:false` 比较的是有限语义/窗口投影；API 已声明视觉变化需看图。**不能把滚动后这个字段不变单独判为错误。** 应改进的是相关内容的可达性，以及 Agent 对“本次到底观察了什么”的判断。

### 2.3 长字段截断会影响结果验证，优先于性能优化

原始基线的 `scene.rs::text` 无字段标志地截取 name/value 的前 240 字符；后续差分只比较投影。因此，原生值只在被省略的尾部发生变化时，可能无法通过外部 view 区分。这个判断来自源码，本次没有修改长文本实测它。

先让截断和未完整读回明确可见，并使被省略内容的变化能被识别，再讨论减少 PNG 或加速。内容摘要/版本变化只能证明变化，不能冒充全文或末尾文字的读回。

## 3. 一个迭代，三个工作包

### A. 观察与读回补全（P0）

**交付：** Agent 能判断正文和结果是否读全，能取得任务相关内容，不必反复得到相同的前部控件。

1. 给被截断字段提供明确的完整性信息，使尾部变化不再表现为“已完整观察且完全无变化”。先不提高全局预算来掩盖问题。
2. 用本次长页面复现，改进候选的可见性、正文相关性和预算分配；对语义不足明确提供现有 capture/scroll 路径。若这些仍不能完成有界阅读，再评审给现有 `look` 增加定位/阅读参数，优先复用内部原生遍历和文本能力。
3. 在重复列表任务中验证紧凑的行、关联 label 或其他可证明上下文是否足够。保留目标身份与 selector 唯一性，不用“第一个/nth”猜目标。
4. 同步当前 API、能力矩阵与输入路由说明，特别是 macOS 定向输入、hover 借用和不同显示路径的区别。

**验收：**

- 超过 240 字符、末尾含唯一标记的正文：明确告知未读全；尾部变化可被发现；最终通过 UI 读回该标记。
- 超过 80 控件、目标位于后段的长页：能抵达目标，记录观察/截图/定位轮次；不能以 `has_more:true` 算完成。
- 多行同名 Edit/Reviewed 控件：指定两条记录分别修改、各保存一次；独立 journal 证明没有改错行或重复提交。
- 语义降级、目标更新、页面排序和读失败仍保留原有身份/绑定失效规则。

**拥有位置：** `cmd/dtw/src/app_protocol/scene.rs` 的文本投影、候选选择和差分；`selection.rs` 的对象选择；Skill API/PATTERNS。原生 provider 已有能力不等于可以直接恢复旧公共 API。

### B. 当前协议真实任务基线与普通文件流程（P0）

**交付：** 一套可以重跑的当前 `apps/exec` 任务链和报告；优先修复其中阻断普通任务的兼容问题。

复用现有 fixture、数据准备和独立 oracle，迁移 acting Agent 的调用与 transcript/metrics 解析。历史 runner 继续标为历史；不把历史报告改名当作当前通过。先固定一个主要 Harness/模型组合，其余已支持接入验证同合同和必要任务，不把全面模型 A/B 作为本轮前置。

| 核心任务 | 必须读回的效果 |
| --- | --- |
| Chrome 长页与分页列表 | 后段内容可读；指定记录保存、重开一致；邻接记录和提交次数正确 |
| WPS 多语言编辑、另存、关闭重开 | 新文件内容正确，原文件不变，重开后的 GUI 内容一致 |
| Obsidian 新 vault、链接、搜索重开 | vault 和 Markdown/链接正确；GUI 搜索及打开到达指定内容 |
| 原生 Open/Save、取消及已有文件确认 | 实际文件名/内容正确；取消没有多余写入；helper 归属和输入接收可证明 |
| 同 app 双窗口和延迟完成 | 只改指定文档；保存只派发一次，靠后续读取确认，超时保留不确定性 |

macOS 首轮使用上述 Chrome/WPS/Obsidian 任务；Windows 先沿用已具备环境的 Chrome/Edge 与自有原生 fixture，覆盖相同合同。其他应用按实际安装条件补充，不要求把所有平台、应用、Harness 和模型做全排列；X11 后续也复用任务目的及 oracle，而非要求同一个应用。

**Windows 优先复现条件：** 普通文件选择时，把鼠标保留在正常交互位置，让 tooltip/shadow 自然出现。已有最终 14/14 采用预先停放鼠标；这证明已验收条件下可完成，不代表这个阻塞已彻底消除。

先收窄到能证明归属的标准文件对话框及装饰层，建立正确合成/接收路线，使普通选文件无需预停放鼠标。未知浮层和未证明的 per-pixel alpha 仍明确拒绝。若最小修复需要新增捕获路线，必须验证 resize、取消、帧更新和资源回收；仅“换成 WGC”不算方案完成。任意透明窗口的全面支持另列扩展项。

**报告和完成标准：**

- 固定源码、最终安装包、配套 Skill、模型、Harness、应用版本与桌面条件，确认图像实际进入模型上下文。
- 每项核心任务至少两次独立运行；完整保留失败尝试及人工提示。两次通过用于本轮重复性检查，不推导总体成功率。
- 记录任务/子目标完成、总时间、模型用量（宿主可提供时）、MCP 次数、只读刷新、PNG 字节、错误及恢复轮次、重复写入数。原生调用耗时和模型等待分别记账。
- fixture、直接脚本、真实 Agent、最终安装包分别标记；开发探针通过不替代最终安装连接上的任务结果。
- `app_client.py` 现有秒数/JSON 字节/图片数量指标可以复用，但要补任务和恢复维度；旧 runner 的 `value.calls`/`script.summary` 解析必须迁移。

### C. 后台干扰与桌面不可用时的中断恢复（P1）

**交付：** 可执行的操作矩阵，以及失去桌面/权限后有界、可解释的停止和恢复。先审计、补失败用例，再按已证实缺口修改。

矩阵按平台、框架和动作区分：语义点击、坐标左右/双击、滚动、键盘、hover、内容拖拽、标题栏移动。分别验证目标效果、真实光标、前台窗口、用户键盘目的地和拒绝前副作用，不用单个“后台成功”结论替代。

- macOS 的已验证定向点击/拖拽/滚动沿用现状；原生 hover 借用是明确边界。独立 hover 只做有截止条件的研究，有新证据再替换，不能阻塞本轮结束。
- 严格 `background-only` 下，不支持的动作应在准备/输入副作用前拒绝。验收严格模式，而不是把普通模式的物理借用计作不干扰。
- 对锁屏、输入桌面切换、权限撤销及连接中断，先核实现有诊断与行为。Windows 已有 input-desktop 诊断，不能直接据此声称跨平台锁屏检测/恢复合同已完整实现。
- 对不能继续的路线停止新输入，有界收尾已持有输入，保留 `not_dispatched/dispatched/unknown`；恢复后重建观察和绑定，不重放原动作。等待用户解锁交给 Harness，单次 DTW 调用保持有界。

**验收：** 使用独立的目标效果和系统光标/前台/键盘观察；覆盖动作前不可用、执行中切换、取消、EOF，以及恢复后的新读取。GUI 故障注入在专用桌面串行运行，不在普通 CI 或用户正在工作的主桌面自动锁屏。没有本平台证据的项标为未验证。

## 4. 排序、并行和退出条件

建议以三个可独立评审的增量推进：A 先修读回正确性；B 的 runner 迁移可并行，用任务结果确定 Windows 兼容修复；C 复用这些任务补干扰/恢复矩阵。最终冻结同一候选，重跑受影响任务和安装连接。

本轮结束需要：

1. 观察完整性、尾部变化和后段内容可达性用例通过；没有以省略内容冒充结果读回。
2. 核心任务在固定条件下可重复完成；普通文件流程不存在要求人工预停放鼠标的已知阻塞，或明确收窄尚未达到的支持承诺。
3. 无已知改错应用/窗口、串入用户键盘、未知效果自动重放、重复业务写入、残留按键/按钮或资源未收尾缺陷。
4. 工具、Skill、当前支持文档和最终安装包证据对应一致；未验证条件和明确扩展边界单列。

达到以上条件后启动 X11。混合 DPI、所有 helper、所有后台手势或所有应用并非无限期的前置条件。性能先分解测量；只优化有证据的重复读取、编码和模型输出，不取消每次派发需要的身份、几何和接收者验证。

## 5. 单列的扩展与条件验收

- **已有实现的条件验收：** Windows AUMID GUI 启动、更多 Open/Save helper、完整窗口迁往另一显示器、混合缩放/负原点/热插拔。按实际任务阻断程度选入当前迭代；不把其他配置未验证表述为整个能力不存在。
- **明确扩展：** 跨窗口/app DnD、更多拖拽形状、剪贴板、窗口缩放、任意 per-pixel layered alpha、exact-tab/DOM/CDP、远程传输。需要自己的依赖闭环和平台验收。
- **后续运行模式：** 独立 X11 桌面持续运行；原锁定会话持续操作或受控解锁/重新锁定属于不同项目。它们不由“支持后台输入”自动获得。

## 6. 移交 X11 的参考基线

本轮移交任务、独立 oracle、指标定义、目标/场景合同、失败恢复及资源回收用例；不要求 X11 模仿 macOS 的全部实现细节。

X11 当前仍是 experimental/unverified：本地 native X11、EWMH、XRes 1.2、XI2、XTest；运行目标发现；无遮挡 client capture 和有限键盘映射；无 AT-SPI、无 move/drag，native Wayland/XWayland 明确不支持。源码和类型检查不构成 GUI 通过。

下一阶段再确定单一参考环境，按“场景与捕获 → 最小语义 → 可靠输入 → 安装与任务验证”推进，并复用本轮任务。独立 X server、D-Bus、profile、生命周期和输入资源隔离随后单独验证；不能仅凭不同 DISPLAY 字符串宣称互不干扰。首个 Alpha 的具体发行版/窗口管理器在该阶段确定，本轮不提前承诺所有 Linux 桌面。
