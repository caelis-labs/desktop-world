# v0.1.0-rc.3: macOS Chrome checkbox 语义修复

修复 [Issue #22](https://github.com/caelis-labs/desktop-world/issues/22)。macOS Chrome 154 在完整 AX 模式下同时报告 checkbox 的数值 `AXValue` 可写与 `AXPress`，但对 `AXValue` 写入返回成功而不改变 DOM，也不发送 `input`/`change`。`set_checked` 现在从新鲜的 0/1 状态判断是否需要更改：已满足时不发送；未满足时优先执行一次广告的 `AXPress`，随后按原机制验证。无数值状态或无受支持语义动作时拒绝能力广告。Chromium 的只读 checkbox 即使广告 `AXPress`，也因为 `AXValue` 不可写而拒绝。其他 provider 的数值 setter 和 AppKit 的 press-only checkbox 保留。

## 本次实机证据边界

- macOS 27.0.1 arm64 / Chrome 154.0.8037.98，独立私有 profile、合成页面、唯一控件、一次原始请求；直接 `host.Start` 调用新构建 helper。`checked=false→true→true→false` 的回执分别为 `complete/verified`、`not_applicable/verified`、`complete/verified`；原请求 `Reconcile` 返回相同 RunID。独立 Chrome DOM 记录仅两组 `input`/`change`，对应 true 和 false。禁用控件在投递前拒绝。
- 同机新私有 profile 的 reduced AX 模式报告空 `AXValue`、无 `AXPress`；`set_checked` 不广告，原请求 `delivery=none`，DOM 保持 false，事件 0。新私有 profile 的 `aria-readonly=true` checkbox 有 `AXPress` 但 AXValue 不可写；同样拒绝且 DOM 不变。
- 新 helper 的 AppKit F7 checkbox 和 mixed 拒绝、AppKit F6 多选、系统 WebKit F8 滚动均通过独立应用日志验证。Electron 44.5.1 的独立 checkbox fixture 也通过 `true→true→false`，应用自身日志只有两组 `input`/`change`。Electron 完整 fixture 前 11 个操作及业务日志通过；随后原生上下文菜单步骤因 `ambiguous_target` 在绑定前停止，未把该轮记为全通过。

以上是候选 helper 的局部实测。正式发布包的提交、二进制哈希、命令结果、各平台签名状态和下载后核验以 Release 附件 `ACCEPTANCE.json` 及 `SHA256SUMS` 为准。Windows 本轮没有 GUI 实机复测，Windows 资产仅表示同提交原生 runner 构建与自动测试通过，不沿用 rc.2 二进制。macOS 包按仓库脚本 ad-hoc 签名且未公证；Windows 包未签名。语言 SDK 注册表未发布。

## 复现与验收入口

在新建的私有 Chrome profile 中，以 `--force-renderer-accessibility` 打开 [合成 checkbox 页面](../../tests/native-fixtures/browser/chrome-checkbox.html)，用唯一 `?run=...` 区分窗口。选定精确窗口标题和控件名，设置 `DTW_NATIVE_HELPER`、`DTW_CHROME_TITLE`、`DTW_CHROME_CHECKBOX`、`DTW_CHROME_DISABLED`、`DTW_CHROME_ONCE`、`DTW_CHROME_EVIDENCE`，执行 `go test ./tests/acceptance -run '^TestNativeChromeCheckboxDesiredState$' -count=1 -v`。`DTW_CHROME_ONCE` 必须是尚不存在的新路径；失败或 unknown 时只查同一请求回执，不能换 ID 重发。使用页面自己的 DOM/event log 独立核对动作，不把 AX 状态或 `delivery=complete` 当作业务效果。reduced AX 和只读拒绝使用 `TestNativeChromeCheckboxUnavailable` 及相应 `DTW_CHROME_UNAVAILABLE_*` 环境变量。

完整构建、race/vet、跨平台测试与对应源码检查见 `scripts/check.sh`、CI 和 `scripts/package-prerelease.sh` / `.ps1`。发布包须在合并提交上构建，manifest、源码归档、许可文件和 SHA256SUMS 逐项一致。
