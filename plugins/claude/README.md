# Desktop World

Inspect and operate running desktop applications through standard MCP tools using app-scoped JavaScript or flat native operations.

This is a local development plugin staged from a source build. It includes Agent Plugins 1.0, Claude Code, Antigravity and DSH Cordis entries around one executable and the Desktop World Skill. Choose one route in each host; do not register both plugin and manual MCP/Skill copies. Follow [the installation guide](https://github.com/caelis-labs/desktop-world/blob/main/install.md) and the [Caelis](https://github.com/caelis-labs/desktop-world/blob/main/docs/install-caelis.md), [DSH](https://github.com/caelis-labs/desktop-world/blob/main/docs/install-dsh.md) or [Antigravity App/CLI](https://github.com/caelis-labs/desktop-world/blob/main/docs/install-agy.md) instructions. Packaged copies also include these guides at their root and under `docs/`. Claude Code can load this directory with `claude --plugin-dir /absolute/path/to/plugin`.

Default `dtw mcp` advertises `apps` and `exec`; opt in with `dtw mcp --atomic` for `apps` plus fourteen flat app operations without JavaScript. Discover/list actual tools: use scripts when `exec` is present; otherwise invoke the listed operation directly. Search with `apps({query})`, then pass the discovered `app` identity to `exec({app,source})` or each atomic operation. Both use the same object fields, with atomic calls adding `app`; JS shorthand remains a compatibility convenience. For example, `await app.typeText({text:'Hello'})` corresponds to `typeText({app,text:'Hello'})`.

The bundled Skill and self-contained API.md define `look`, `capture`, `readText`, `wait`, `waitForNewWindow`, `click`, `setValue`, `move`, `drag`, `typeText`, `keypress`, `scroll`, `focus` and `quit`. Observe when needed with `look({})` or `capture({})`; known actions need no redundant initial look. DTW owns startup, routing, references and post-input observation. Scripts can batch known actions and customize output with `return`/`print`. Each atomic call settles its own execution boundary; keep related focus/input and Windows menu-open/item selection in one `exec`. No public Session or receipt-query tool is needed. Verify application effects; never replay unknown actions. See [MCP toolsets](https://github.com/caelis-labs/desktop-world/blob/main/docs/mcp-toolsets.md) for configuration and compatibility.

The Harness owns tool approval. macOS 14.2+ arm64 operations need the corresponding Accessibility or Screen Recording permissions. Windows x64 uses native UIA and input delivery, with foreground access managed by DTW when needed. This development stage still needs acceptance on its exact bytes; prior release acceptance does not certify a rebuilt binary. Browser DOM and locked-session input remain outside the runtime contract. Host execution/file restrictions also apply; use a supported, authorized launch path and the host's normal approval process if access is denied. Never change sandbox policy or ACLs to make installation succeed. Switching apps retains each app’s committed state and still-valid references. References can expire or be consumed by actions; rediscover them when needed.

This local stage is not a signed or notarized release package. Build identity and retained source/license notices are included alongside the executable; public distribution requires separate release validation.
