# Desktop World

Call `exec` with `{"session":"task-name","script":"..."}`. Short scripts usually return a terminal result in the same call (default wait 4 seconds; `wait_ms` accepts 0–5000). If `status` is `running`, query the **same** tool with `{"session":"task-name","operation":"result","execution_id":"..."}` until terminal. `status` and `cancel` use that original id. Cancellation can be pending while native input finishes; never replay an `unknown` action.

Scripts are CUA `run_script` bodies: `await` and `return` work; `cua` and a JSON `state` object are available. No filesystem, network, process or Node API exists. Mutations to `state` persist after a successful script. For an exact target, run `const windows=await cua.listWindows({pid:123}); return windows;`, select its `window_id` by title, then `const app=await cua.getApp({pid:123,windowId:456}); const view=await app.getState({max_elements:100}); return {pid:app.pid,window_id:app.windowId,tree:view.tree_markdown,snapshot_id:view.snapshot_id};`. Bind that same PID/window in the next script.

Common native signatures (selectors are `{role?,name?,text?,nth?}`, or a fresh element token, row number, or window pixel `[x,y]`): `app.query({role:"textfield",name:"Message"})` returns matches; `app.click(selector)` presses one; `app.typeText("text", selector)` puts **text first**; `app.setValue(selector,"text")` puts **selector first**; `app.waitFor({name:"Choose green"},{timeout_ms:3000})` waits for dynamic UI; `await cua.sleep(250)` pauses without a CPU spin; `app.pressKey("cmd+s")` sends keys; `app.drag([x1,y1],[x2,y2])` drags. A query accepts `name` but returned matches expose their text as `label`; broad queries normally cap at 50 matches, so narrow the name. If a displayed `AX` role is unclear, query by exact `name` first instead of guessing a role. Example: `await app.typeText("hello",{role:"textfield",name:"Message"}); await app.click({role:"button",name:"Apply"}); const s=await app.getState({max_elements:80,include_screenshot:false}); return {tree:s.tree_markdown,truncated:s.truncated};`. On a large web page, raise `max_elements` only as needed and return filtered facts rather than the whole tree. `app.getState()` includes a screenshot by default; read its retained image only when needed.

Use `{"operation":"permissions"}` for a promptless host permission read. Use `{"session":"task-name","operation":"cursor","enabled":true}` to show that Session's virtual cursor, omit `enabled` to inspect it, and set `false` when done. Cursor operations follow the same terminal-or-running result rule.

If a native dialog or canvas requires persistent foreground focus, call `exec` with `{"session":"task-name","operation":"focus","pid":123,"window_id":456}` for a known ordinary window. Check `focus.activated`, `focus.verified`, and `focus.focused_window_id` in its terminal receipt; request acceptance alone is not focus proof. This leaves the app in front, so reserve it for an isolated target. After opening an Open/Save panel, **rebind** with `const panel=await cua.getApp({pid:parentPid}); const s=await panel.getState({max_elements:100}); return {window_id:panel.windowId,tree:s.tree_markdown};` and verify that the returned window is the chooser before acting. A persistent Obsidian chooser was selected this way. If that does not find it, compare global `cua.listWindows()` before/after: the service process may own an invisible window while the parent app exposes a separate visible `open-panel` window with the actionable AX tree. Check both owners, `layer`, `is_on_screen`, and bounds; bind the visible app-owned panel by exact PID/window ID and query its controls. Only focus an exact, stable, visible ordinary window; stop if the modal's focus or editable control cannot be verified. Do not focus the parent main window while its modal is open. A WPS plus-menu may be an in-app overlay; inspect the screenshot and control tree after clicking, and do not infer success from AXPress alone. `cmd+n` may open a blank document directly; confirm its title before editing.

`result` returns a bounded summary. A successful script's native `text` omits its duplicate `return value`; use the separate `value` field. Request `part:"structured"` or `part:"text"` with `offset` to page the full receipt, or `part:"image"` with `image_index` to view a retained screenshot. Screenshot and large trees are kept out of the ordinary text reply. An input receipt is delivery evidence; read back the changed UI or file before claiming task success. After a stale element, observe again. macOS permissions belong to the actual host; a permission refusal is not an action.

Session labels separate script `state` and execution receipts and map to CUA trusted Sessions, but native element tokens can cross labels in one worker. Reobserve before acting when another Agent may have changed the desktop; use a separate MCP process per independent Agent host.

For a canvas editor with no AX text element, get a screenshot in the same Session, inspect its retained image, then use `await cua.call("type_text", {pid,window_id,x,y,text,delivery_mode:"foreground"})` with a point on that editor. The pixel form focuses and types in one native action. If background keys fail, use `await cua.call("hotkey", {pid,window_id,keys:["cmd","s"],delivery_mode:"foreground"})` on the exact window and verify the saved file. A foreground action briefly activates the target, then restores the prior app.
